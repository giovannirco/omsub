# Cursor plugin 0.6.5

## Context metadata correction

- Replace the universal 200,000-token context declaration with authenticated
  Cursor `AvailableModels` metadata matched to usable model IDs.
- Use positive default-mode limits and exact names, aliases and non-MAX variant
  slugs. Duplicate MAX variants cannot inflate the executor's advertised limit.
- Omit unknown context limits and the previously unverified 32,768-token output
  ceiling. Unknown does not mean unlimited.
- Refresh metadata on account model discovery, with a 15-second request deadline
  and a 4 MiB response bound. Metadata failures remain explicit errors.
- Preserve account model exclusions and the existing default execution mode.

## Verification and limits

Regression tests cover dynamic capacity changes, default/MAX duplicates, aliases,
disabled IDs, static/unknown limits, invalid metadata and upstream failures.
The full plugin race/shuffle test suite, vet and build passed locally on Go 1.25.14.

Authenticated catalog observations on 2026-09-28 returned default context limits
of 256,000 for `grok-4.7-xhigh-fast`, 300,000 for
`claude-fable-5-1-thinking-xhigh`, and 272,000 for `gpt-5.6-sol-xhigh`.
These values are observations, not constants embedded in the plugin.

A synthetic Grok request through the candidate plugin carried 210,000 filler
words and recovered all three start/middle/end markers. This is a long-input
transport check, not an exhaustive token-boundary test. Plugin usage counts are
estimates rather than upstream tokenizer measurements. See
[context metadata details](../cursor-context-limits.md).

This release does not enable MAX mode, change client compaction settings, alter
CPA host code, or resolve the separate web-search/fetch progress timeout.
Production deployment and client catalog refresh are separate acceptance steps;
publishing these artifacts alone does not prove either has occurred.

## Installation

Use `cursor_0.6.5_linux_amd64.zip` for the plugin store or
`cursor-plugin-0.6.5-linux-amd64.tar.gz` for manual installation. Verify the files
against the same release's `checksums.txt`, back up the current plugin, replace
only `cursor.so`, and restart CLIProxyAPI. Refresh the client's model list if it
caches capacity metadata. Existing explicit client limits are not overwritten.
