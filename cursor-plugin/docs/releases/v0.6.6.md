# Cursor plugin 0.6.6

## Resource limits and availability

- Bound executor envelopes before the native ABI copies memory, then apply one
  full-history admission policy to execute, streaming execute and token counting.
- Publish native non-MAX capacity separately from the 1,000,000 client policy.
  Unknown native capacity is omitted. Effective capacity is capped at the policy.
- Preserve usable model IDs when optional capacity metadata fails; bound both
  discovery requests to 15 seconds and 4 MiB.
- Make session waits cancellable, with eight waiting followers per session,
  64 active/waiting session-backed turns per handler, and a 30-second wait limit.
  Overload returns request-scoped HTTP 409 without account cooldown or auto-retry.
- Include opaque blob keys in per-entry and total retained-byte accounting.
  Overwrites, capacity reclamation, and rejected-write atomicity are preserved.
- Honor explicit output limits with local conservative accounting, cancel the
  upstream stream at the boundary, and finish JSON/SSE with `length`. Never emit
  a partial tool call or commit a truncated turn as a reusable checkpoint.

## Compatibility and limits

There is no verified common native tokenizer across the supported Cursor models.
The 1M admission policy and explicit output budgets use conservative UTF-8 bytes,
not exact native tokens. Input JSON alone may not exceed 983,616 bytes; parsed
content overhead and explicit output reserves can lower this further. Requests
and outputs below the real model's token limit can therefore be stopped early.
See [the complete policy](../cursor-context-limits.md) before upgrading.

Unknown output ceilings remain unadvertised. Zero/omitted output limits retain
unspecified generation behavior. Image payloads, hidden upstream context, and
already performed upstream work are not a precise token or billing guarantee.
MAX mode, credentials, client compaction settings and CPA host code are unchanged.
The separate web-search/fetch progress timeout is not part of this release.

## Installation

Use `cursor_0.6.6_linux_amd64.zip` for the plugin store or
`cursor-plugin-0.6.6-linux-amd64.tar.gz` for manual installation. Verify both with
the release's `checksums.txt`. Back up the installed plugin, replace only
`cursor.so`, and restart CLIProxyAPI. Publication alone is not production
acceptance; verify the loaded version, capacities, ordinary chat, streaming,
tool continuation and oversized-input rejection after deployment.
